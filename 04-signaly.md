# Задание 4. Сигналы: SIGTERM против SIGKILL

### Часть А. Упрямый процесс

Создание скрипта `nano ~/upryamy.sh` : 
```
#!/bin/bash
trap 'echo "Получил SIGTERM, но продолжаю работать"' TERM
echo "Мой PID: $$"
while true; do sleep 1; done
```
Скрипт перехватывает сигнал SIGTERM и вместо завершения выводит сообщение, после чего продолжает работать

Создание исполняемым файл `chmod +x ~/upryamy.sh` и запуск `~/upryamy.sh &`
```
[1] 1740
user@debian:~$ Мой PID: 1740
```
[1] — номер фоновой задачи, а 1740 — PID процесса.

После просьбы завершения, получил вывод:
```
Получил SIGTERM, но продолжаю работать
```
Это означает, что скрипт получил SIGTERM, но благодаря команде trap перехватил сигнал и продолжил работу


Проверка на живой процесс `ps -p 1740 -o pid,stat,cmd`.
```
    PID STAT CMD
   1740 S    /bin/bash /home/user/upryamy.sh
```
`S` означает, что процесс находится в состоянии ожидания (sleeping), но продолжает работать.


Теперь принудительное убийство процесса
```
kill -KILL 1740
ps -p 1740 -o pid,stat,cmd
```
В отличие от SIGTERM, SIGKILL нельзя перехватить или проигнорировать.

### Часть Б. Передний план и фон.

1. `sleep 600` - запускает процесс sleep на 600 секунд на переднем плане. Пока он работает, терминал занят этим процессом.
```
^Z
[1]+  Остановлен    sleep 600
```
2. `ps -o pid,stat,cmd -C sleep` - показывает процессы с именем `sleep` и выводит их PID, состояние и команду.
```
    PID STAT CMD
   2036 T    sleep 600
```
Буква T означает, что процесс остановлен или приостановлен сигналом управления заданиями.

3. `bg %1` - возобновляет выполнение задания №1 в фоновом режиме.
```
[1]+ sleep 600 &
```
Теперь sleep продолжает работать, а терминал снова доступен для команд.

4. `jobs` - показывает задания текущей оболочки и их состояние.
```
[1]+  Запущен          sleep 600 &
```

5. `fg %1` - переводит фоновое задание №1 обратно на передний план.
```
sleep 600
```
Теперь терминал снова занят процессом sleep.


## Итоговый отчёт

1. Объясните, почему скрипт пережил SIGTERM, но не пережил SIGKILL

> SIGTERM — это обычный сигнал завершения. Программа может его перехватить и выполнить свои действия перед завершением или вообще продолжить работу. SIGKILL нельзя перехватить, заблокировать или обработать программой. Ядро немедленно завершает процесс.

2. Ответьте: почему правильный порядок — сначала SIGTERM, и только потом SIGKILL?

> Сначала используют SIGTERM, потому что процессу дают возможность корректно завершиться: сохранить данные, закрыть файлы, освободить ресурсы и выполнить очистку.

3. Что может пострадать при немедленном kill -9 у базы данных?

> Для базы данных немедленный kill -9 может прервать операции записи и другие действия до их корректного завершения. Это может привести к незавершённым операциям и необходимости восстановления данных при следующем запуске.

4. Какую букву состояния получил sleep после Ctrl+Z и что она означает

> Процесс получил состояние: `T`. Означает остановленный (stopped) процесс. Он остаётся существовать, но временно не выполняется. Команда `bg` возобновляет его в фоне, а `fg` - на переднем плане.

5. Какой сигнал посылает Ctrl+C , а какой — Ctrl+Z
- Ctrl+C > SIGINT — прерывает выполняемый процесс.
- Ctrl+Z > SIGTSTP — приостанавливает процесс.

При этом Ctrl+Z не завершает процесс, а переводит его в состояние остановки `T`.
