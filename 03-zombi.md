# Задание 3. Зомби-процесс своими руками

1. `bash -c 'sleep 1 & exec sleep 120' &` - Запускается новый Bash в фоновом режиме. Внутри него запускается sleep 1, который завершается через 1 секунду. Затем `exec sleep 120` заменяет Bash процессом `sleep`, который будет работать 120 секунд.
```
[1] 1688
```
- [1] - номер фоновой задачи в текущем Bash.
- 1688 - PID запущенного фонового процесса.

После завершения sleep 1 его родительский процесс ещё работает, поэтому завершившийся процесс становится зомби.

2. `ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'` - выводит список всех процессов с указанными полями: PID, PPID, состояние и команду. `awk '$3 ~ /Z/'` оставляет только процессы, состояние которых содержит Z

```
   1689    1688 Z    [sleep] <defunct>
```
Процесс `sleep` с PID 1689 завершился, но его родительский процесс 1688 ещё не забрал информацию о его завершении. Поэтому процесс находится в состоянии Z и имеет пометку `<defunct>`.

3. `ps -o pid,ppid,stat,cmd -p 1688` - Команда выводит PID, PPID, состояние и команду процесса с PID 1688.

```
[1]+  Завершён        bash -c 'sleep 1 & exec sleep 120'
```
То есть процесс 1688 уже завершился. После его завершения зомби 1689 также должен быть обработан системой.

## Итоговый отчёт

1. Объясните, почему kill -9 не подействовал на зомби
> Зомби уже не выполняет код и не является работающим процессом. Он представляет собой запись о завершившемся процессе, которая сохраняется до тех пор, пока родитель не получит информацию о его завершении.

2. Объясните, почему зомби исчез после завершения родителя.

> Когда родительский процесс завершается, его дочерний процесс становится сиротой. Сироту усыновляет специальный процесс PID 1 (systemd) или другой назначенный системой процесс-усыновитель.


3. Чем опасна ситуация, когда в системе тысячи зомби
> Тысячи зомби могут заполнить таблицу процессов системы. В результате система может перестать создавать новые процессы, из-за чего перестанут нормально запускаться программы и службы.
